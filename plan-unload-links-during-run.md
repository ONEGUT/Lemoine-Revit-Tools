# Plan — Temporarily unload linked models for the duration of a run

Status: **proposal, awaiting approval.** No code written yet.

---

## 1. Feasibility: yes, but with a different API than the obvious one

Verified against `libs/RevitAPI.dll` by walking the metadata tables with `dnfile`
(`TypeDef` → `MethodList`, decoding each signature blob) — **not** a string search,
per the Research Discipline rule. Confirmed surface on `Autodesk.Revit.DB.RevitLinkType`:

```
LinkLoadResult          Load()
LinkLoadResult          Reload()
void                    Unload(ISaveSharedCoordinatesCallback)
bool                    UnloadLocally(ISaveSharedCoordinatesCallbackForUnloadLocally)
LinkedFileStatus        RevertLocalUnloadStatus()
bool                    LocallyUnloaded { get; }          // getter only, no setter
static bool             IsLoaded(Document, ElementId)
LinkedFileStatus        GetLinkedFileStatus()
bool                    IsNestedLink { get; }
ElementId               GetParentId()
ElementId               GetRootId()
ICollection<ElementId>  GetChildIds()
bool                    HasSaveablePositions()
bool                    SavePositions(ISaveSharedCoordinatesCallback)
bool                    IsNotLoadedIntoMultipleOpenDocuments()
```

Supporting enums, also read from metadata:

```
LinkedFileStatus      : Invalid, Loaded, Unloaded, Imported, NotFound,
                        CanBeUpgraded, InClosedWorkset, LocallyUnloaded
LinkLoadResultType    : Uninitialized, LinkLoaded, LinkNotFound, LinkNotOpenable,
                        LinkOpenAsHost, SameModelAsHost, SameCentralModelAsHost,
                        LinkNotLoadedOtherError, LinkMayBeUpgraded,
                        ExternalServerMissing, LinkExists,
                        CouldNotChangeViewReference, UsedExisting
SaveModifiedLinksOptions                  : SaveLinks, DoNotSaveLinks, DisableSharedPositioning
SaveModifiedLinksOptionsForUnloadLocally  : SaveLinks, DoNotSaveLinks
```

### 1.1 Use `UnloadLocally` / `RevertLocalUnloadStatus`, never `Unload` / `Load`

This is the single most important finding.

- **`Unload()` writes the unloaded state into the model.** In a workshared project that
  travels to central on the next sync and *every other user sees the links unloaded*.
  Using it for a transient speed trick would be destructive to the team.
- **`UnloadLocally()` is the per-user variant** — it produces
  `LinkedFileStatus.LocallyUnloaded` and sets the read-only `LocallyUnloaded` property.
  `RevertLocalUnloadStatus()` puts it back. That pair, and only that pair, is correct here.

The repo already calls `loadedType.Unload(null)` in
`UpgradeLinksRunHandler.UnloadIfCurrentlyLinked` (`Source/Tools/Setup/UpgradeLinksRunHandler.cs:740`).
That is correct **there** — it is a permanent re-point followed by a `LinkIntoHost` reload —
but it is the wrong call for this feature. Nothing in the plan changes that call site.

### 1.2 The two callback interfaces are not interchangeable

```
ISaveSharedCoordinatesCallback
    SaveModifiedLinksOptions                 GetSaveModifiedLinksOption(RevitLinkType)

ISaveSharedCoordinatesCallbackForUnloadLocally
    SaveModifiedLinksOptionsForUnloadLocally GetSaveModifiedLinksOptionForUnloadLocally(RevitLinkType)
```

Different method name **and different return enum**. Passing `null` risks Revit raising its
own save-shared-coordinates prompt when `HasSaveablePositions()` is true — which, per the
"tool window is not owned to Revit" note in CLAUDE.md, can render *behind* the tool window
and look like a hang. Implement a tiny callback returning
`SaveModifiedLinksOptionsForUnloadLocally.DoNotSaveLinks` instead of passing `null`.

### 1.3 Transaction rule

Per the existing CLAUDE.md constraint (confirmed on a Windows run for `Unload`):
`Load`/`Unload`/`Reload`/`LoadFrom` throw *"The operation is not permitted when there is any
open transaction phase started by API client"*. So `UnloadLocally` and
`RevertLocalUnloadStatus` must bracket the run's `Transaction`, never sit inside it.
The plan assumes `UnloadLocally`/`RevertLocalUnloadStatus` share that rule — **flagged for
Windows verification** (§6), since only `Unload` has actually been proven here.

### 1.4 Not undoable

No transaction means no undo entry. If the run throws past the restore, or Revit crashes,
the links stay locally unloaded with nothing in the undo stack to fix it. This needs a
`try/finally` **and** a persisted breadcrumb (§4.2).

## 2. The performance premise — true, but not for the reason it sounds like

Being blunt about this, because it determines which tools are worth touching.

`doc.Regenerate()` regenerates the **host** document. Linked models are separate `Document`s
and are *not* regenerated by it. So "regen is slow because of links" is not right as stated,
and bolting the option onto every tool that calls `Regenerate()` would add risk for no gain
on several of them.

Links dominate cost in three specific places, and only these are worth targeting:

1. **View-graphics resolution** — anything that forces Revit to compute what is *visible* in
   a view: `Viewport.Create` → `Regenerate` → `GetBoxOutline()`, view duplication with
   detailing, crop/scale changes. Linked geometry is part of the visible set, so this scales
   with link size. **Real, large win.**
2. **Export / print rendering** — PDF/DWG/NWC/IFC walk the full visible set per view.
   **Biggest single win**, and also the most dangerous (§3.3).
3. **Host elements that reference linked geometry** during regen — dimensions and tags to
   linked elements, rooms/spaces bounded by linked walls, face-hosted families on link faces,
   Copy/Monitor. **Win here is real but this is also hazard #2 below** — the same references
   are what breaks.

Host-geometry work with no view-graphics component (the `Modify/Split*` tools, Legend
Creator, Bulk Rename) gets essentially nothing. Excluded.

## 3. Correctness hazards — these, not the API, are the hard part

### 3.1 Crop-inactive viewport measurement silently changes

`Viewport.GetBoxOutline()` for a view with `CropBoxActive == false` is the extent of the
view's **visible geometry**. Unload the links and that footprint shrinks. Place Dependent
Views and Align Sheet Views would then size and pack viewports against a footprint that stops
being true the moment the links come back — wrong drawings, no error, no log line.

This is a correctness bug, not a speed/quality trade-off. Gate accordingly:

- **Place Dependent Views**: allowed in `LayoutMode.Estimate` only (it sizes from the crop box
  and never measures — `PlaceDependentViewsEventHandler.cs:329-374`). Blocked in
  `Accurate`/`Grouped`, which measure.
- **Align Sheet Views**: allowed only when every view in the run is `CropBoxActive`; the tool
  already tracks this distinction (`dv.CropBoxActive` at
  `PlaceDependentViewsEventHandler.cs:399`), so the check is cheap. Otherwise the option is
  hidden, not disabled — per the UX rule about only presenting choices that work for the
  current input.

### 3.2 Rooms, spaces and link-referencing annotation change meaning

Rooms bounded by linked walls become unenclosed while the links are gone; areas and volumes
recompute. Any tool that *reads* room data mid-run gets wrong values, and "room not enclosed"
warnings land in the run log via `RevitFailureCapture`. Dimensions and tags referencing linked
geometry report as unreferenced.

This rules out the option for every tool in Tier C (§4.1) by construction — they are exactly
the tools that read this data.

### 3.3 For exports, unloading changes the deliverable

A PDF exported with links unloaded is a PDF **with the linked models missing from it**. On a
coordination sheet set that is a silently wrong issue. So for Bulk Export and Print View this
can never be a quiet "make it faster" toggle — it is a content decision and must be labelled
as one ("Exclude linked models from output — faster, and they will not appear"), off by
default, and echoed in the review step and the run log.

Worth saying plainly: for exports the *correct* mechanism is per-view link visibility or a
view template, not a global unload. The unload is only justified because it is dramatically
faster than editing visibility per view across a large set.

### 3.4 Reload is not free

`RevertLocalUnloadStatus()` re-reads the link files. For a set of large links that is minutes,
not seconds. Below some run size the option makes the tool **slower**. Mitigation: report the
restore time in the run log so the user can judge it themselves, and do not default it on
anywhere.

### 3.5 Smaller ones

- **Nested links** — operate only on links where `IsNestedLink == false`; children follow the
  parent. Use `GetChildIds()` only for reporting.
- **Already-unloaded links** — snapshot `GetLinkedFileStatus()` per link *first* and only
  revert what this run actually unloaded, or the run "helpfully" loads links the user had
  deliberately unloaded.
- **`IsNotLoadedIntoMultipleOpenDocuments()`** — a link also open elsewhere may behave
  differently; log it and skip rather than guess.

## 4. Design

### 4.1 Which tools get the option

**Tier A — safe, real win, opt-in checkbox:**

| Tool | File | Why |
|---|---|---|
| Views Bulk Duplicate | `Source/Tools/Views/ViewsBulkDuplicateRunHandler.cs` | `View.Duplicate(WithDetailing)` per view, graphics-heavy |
| Views by Template | `Source/Tools/Views/ViewsByTemplateRunHandler.cs` | same |
| Replicate Dependent Views | `Source/Tools/Views/ReplicateDependentViewsRunHandler.cs` | same |
| Place Dependent Views | `Source/Tools/Sheets/PlaceDependentViews/PlaceDependentViewsEventHandler.cs` | **Estimate mode only** (§3.1) |
| Align Sheet Views | `Source/Tools/Sheets/AlignSheetViews/AlignSheetViewsEventHandler.cs` | **crop-active views only** (§3.1) |

**Tier B — content-changing, explicit and loudly labelled:**

| Tool | File |
|---|---|
| Bulk Export | `Source/Tools/Export/BulkExportEventHandler.cs` |
| Print View | `Source/Tools/Export/PrintViewEventHandler.cs` |

**Tier C — must never offer it** (they read linked geometry; the option would break them):
everything under `CopyFromLink/`, `Dimensioning/ClashFinder`, `ClashElevationFinder`,
`AutoDimension` (`LinkRefHelper`, `RoomBoundsResolver`, `SlabEdgeTargetResolver`),
`MakeCeilingGrids*`, `CeilingHeatmap`, `ScopeBoxes/`, `ExplodeViewByTrade`, `AutoFilters`,
`Discover`, `ViewsByLink`, and all of `Setup/`.

**Tier D — no benefit, excluded:** `Modify/Split*`, Legend Creator, Bulk Rename.

### 4.2 New file — `Source/Framework/LinkUnloadGuard.cs`

```csharp
public sealed class LinkUnloadGuard : IDisposable
{
    // Snapshots status, unloads top-level loaded links. Returns null if nothing to do.
    // MUST be called outside any transaction.
    public static LinkUnloadGuard? Begin(Document doc, Action<string,string> pushLog);

    public int UnloadedCount { get; }

    public void Restore();   // idempotent; outside any transaction
    public void Dispose();   // calls Restore()
}
```

Call shape in a handler — note the guard brackets the transaction, it does not wrap it:

```csharp
LinkUnloadGuard? guard = null;
try
{
    if (UnloadLinks) guard = LinkUnloadGuard.Begin(doc, Log);   // outside tx
    using (var tx = new Transaction(doc, "…")) { /* the run */ }
}
finally
{
    guard?.Restore();                                           // outside tx
}
```

Behaviour:

- Collect `RevitLinkType` where `GetLinkedFileStatus() == Loaded` and `IsNestedLink == false`.
- Log `"Unloading N linked models…"` — and `"No loaded links found"` when N is 0, per the
  zero-result rule.
- `UnloadLocally(new NeverSaveCoordinates())`, checking the `bool` return per link; a `false`
  is logged `warn`, not swallowed.
- Restore calls `RevertLocalUnloadStatus()` per link, checks the returned `LinkedFileStatus`,
  and logs any link that did not come back as `Loaded` at `fail` tone plus
  `DiagnosticsLog.Error` — a link left unloaded must be impossible to miss.
- Both phases report elapsed time so §3.4 is visible to the user.

### 4.3 Crash breadcrumb

Because there is no undo (§1.4), `Begin` persists the unloaded links (name + `UniqueId`) to a
per-document `DocScoped` bucket (`Source/Framework/DocScopedValue.cs`) keyed by
`DocumentKey.Current`, and `Restore` clears it on success. This follows the settings-tier rule
— element identity never goes in a machine-wide slot.

On the next command launch (where `DocumentKey.SetCurrent(doc)` already runs), a non-empty
breadcrumb for the current document means a prior run died mid-flight: offer to reload those
links. Scanning for `LocallyUnloaded` alone is not enough — it cannot distinguish links the
*user* unloaded deliberately from ones we left behind.

### 4.4 UI

One checkbox in each adopting tool's options step, wired through settings DTO → step summary →
review row → handler property. Per the CLAUDE.md warning about dead options, the plan's
acceptance check is to **grep the value from the handler property forward to the
`LinkUnloadGuard.Begin` call**, not merely to the property assignment.

Labels differ by tier:
- Tier A: *"Unload linked models during run (faster; reloaded automatically when finished)"*
- Tier B: *"Exclude linked models from output (faster — linked models will not appear in the exported files)"*

### 4.5 Strings

New `Strings/en/linkUnloadGuard.json` for the guard's own log lines; per-tool checkbox labels
go in each tool's existing JSON. All user-facing text via `AppStrings.T`.

## 6. Needs verification on a Windows/Revit run before relying on it

1. **Do `UnloadLocally` / `RevertLocalUnloadStatus` share the "outside any transaction" rule?**
   Only `Unload` has been proven here. This changes the call structure if wrong.
2. **Does `UnloadLocally` work in a non-workshared model?** The API is worksharing-oriented;
   behaviour in a standalone `.rvt` is assumed, not proven.
3. **Actual speedup**, measured: Views Bulk Duplicate and Bulk Export over a real linked
   project, with and without the option, including restore time — this is what decides whether
   Tier B is worth its risk at all.
4. **Does `HasSaveablePositions() == true` still prompt** with the `DoNotSaveLinks` callback in
   place?
5. **Does a locally-unloaded link's per-view visibility/graphics state survive** the
   unload/revert cycle intact?

---

## 7. Recommendation

Build steps 1 and 2. They are the safe, high-value part: a self-contained guard plus three
view-duplication tools where nothing reads link geometry and nothing measures visible extents.

Hold steps 3 and 4 until the step-2 timings are in hand. If the measured win on a real project
is small, Tier B is not worth shipping an option that can silently produce a PDF missing the
coordination models.
